# 修复第64页表格长文本单元格为空问题 Spec

## Why
第64页表格的第三行第二列、第四行第二列、第三行第六列单元格在输出PDF中显示为空。经日志分析，OCR识别和翻译阶段均正常输出了完整内容，问题出在两个阶段：

1. **识别阶段**：`_parse_html_table` 将表格bbox均匀分配给所有行和列（每行26.27pt，每列60.29pt），不考虑单元格内容长度差异，导致长文本列（如"数据来源"列）和短文本列（如"发布年份"列）分配到相同宽度
2. **绘制阶段**：直接使用这些均匀分配的尺寸，长文本在60pt宽的单元格中用12pt字体放不下，5次缩小后仍溢出，兜底写入不检查返回值，文本溢出不可见

## What Changes
- 在识别阶段 `_parse_html_table` 方法中，联合计算列宽和行高：先按内容权重分配列宽，再根据列宽计算每行所需行高（在原始bbox范围内）
- 在绘制阶段 `_draw_translated_table` 方法中，增加文本溢出截断机制作为安全兜底
- 增加单元格文本渲染的日志记录，便于后续诊断

## Impact
- Affected code: `modules/ocr/llm_extractor.py` 中的 `_parse_html_table` 方法（第874-976行）
- Affected code: `modules/pdf_generator.py` 中的 `_draw_translated_table` 方法（第1072-1168行）
- 影响范围：所有LLM OCR识别的表格

## ADDED Requirements

### Requirement: 联合计算表格列宽和行高
识别阶段 `_parse_html_table` 方法 SHALL 联合计算列宽和行高：列宽决定文本换行，行高由换行行数决定。表格总高度不得超过原始bbox高度。

#### Scenario: 第一步 - 按内容权重分配列宽
- **WHEN** 解析HTML表格得到所有单元格文本内容
- **THEN** 系统应按以下策略计算每列宽度：
  1. 对每列，计算所有单元格文本的显示宽度（CJK字符宽度按字体大小×1.0估算，ASCII字符宽度按字体大小×0.6估算）
  2. 取每列的最大显示宽度作为该列的权重
  3. 按权重比例分配表格总宽度到各列
  4. 设置最小列宽为表格总宽度的 10%，避免某列过窄
  5. 如果按权重分配后某列超出最大列宽限制（表格总宽度的50%），则钳位到最大值，剩余宽度重新分配给其他列

#### Scenario: 第二步 - 根据列宽计算行高
- **WHEN** 列宽已按内容权重分配完成
- **THEN** 系统应按以下策略计算每行高度：
  1. 对每行的每个单元格，根据文本内容和列宽估算所需行数：
     - 估算文本总显示宽度（同列宽计算中的方法）
     - 行数 = ceil(文本总显示宽度 / 列宽)
     - 最少1行
  2. 取每行中最大估算行数作为该行的行数
  3. 行高 = 行数 × 单行高度（单行高度 = 估算字体大小 × 行高倍率1.2）
  4. 估算字体大小取表格中已估算的字体大小（来自OCR阶段），若无则默认9pt

#### Scenario: 第三步 - 行高钳位到原始bbox范围
- **WHEN** 所有行高计算完成
- **THEN** 系统应确保表格总高度不超过原始bbox高度：
  1. 计算新的表格总高度 = sum(所有行高)
  2. 如果新总高度 > 原始bbox高度，按比例缩小所有行高使总高度等于原始bbox高度
  3. 如果新总高度 <= 原始bbox高度，保持原始bbox高度不变（行高按比例放大填满原始高度）

#### Scenario: 列宽行高计算后更新单元格bbox
- **WHEN** 列宽和行高联合计算完成
- **THEN** 所有单元格的bbox应根据新的列宽和行高重新计算

### Requirement: 表格单元格文本溢出截断机制（安全兜底）
当表格单元格文本在缩小字体后仍溢出时，系统 SHALL 按以下策略处理：

#### Scenario: 文本在5次缩小字体后仍溢出
- **WHEN** 5次逐步缩小字体（从100%到50%）后 `insert_textbox` 仍返回负值
- **THEN** 系统应尝试截断文本以适应单元格，而非直接用溢出文本兜底写入

#### Scenario: CJK文本截断
- **WHEN** 文本包含CJK字符且无法完整放入单元格
- **THEN** 系统应逐字符截断文本，每次减少1个字符，直到 `insert_textbox` 返回非负值
- **AND** 截断后的文本末尾添加"…"省略号

#### Scenario: 英文文本截断
- **WHEN** 文本为英文且无法完整放入单元格
- **THEN** 系统应按空格分词截断，每次减少1个词，直到 `insert_textbox` 返回非负值
- **AND** 截断后的文本末尾添加"…"省略号

#### Scenario: 所有截断尝试失败
- **WHEN** 即使截断到只剩1个字符+省略号仍无法放入
- **THEN** 使用最小字体（base_font_size * 0.5）强制写入，确保至少显示部分内容

### Requirement: 表格单元格渲染日志增强
系统 SHALL 在表格单元格渲染时记录以下信息：

#### Scenario: 单元格文本溢出
- **WHEN** 单元格文本在5次缩小字体后仍溢出
- **THEN** 日志应记录单元格坐标、文本内容（前50字）、单元格尺寸、最终处理方式（截断/强制写入）

## MODIFIED Requirements

### Requirement: 表格单元格文本渲染策略
原有策略（5次缩小字体+兜底强制写入不检查返回值）修改为：5次缩小字体+截断机制+最终强制写入并检查返回值。

### Requirement: _parse_html_table 行高列宽计算
原有策略（均匀分配行高列宽）修改为：先按内容权重分配列宽，再根据列宽和文本内容联合计算行高，最后将行高钳位到原始bbox范围内。

## 合并分支计划

### 输入参数

执行前需由用户指定以下参数：

- **SOURCE_BRANCH**：被合并的源分支（如 `develop`）
- **TARGET_BRANCH**：合并的目标分支（如 `main`）

### 步骤1：检查当前分支状态
- 使用 `git status` 命令检查当前分支和工作区状态
- 确保没有未提交的修改

### 步骤2：确保源分支是最新的
- 使用 `git pull origin ${SOURCE_BRANCH}` 命令获取最新的远程源分支内容

### 步骤3：切换到目标分支
- 使用 `git checkout ${TARGET_BRANCH}` 命令切换到目标分支

### 步骤4：确保目标分支是最新的
- 使用 `git pull origin ${TARGET_BRANCH}` 命令获取最新的远程目标分支内容

### 步骤5：合并源分支到目标分支
- 使用 `git merge ${SOURCE_BRANCH}` 命令将源分支合并到目标分支
- 处理可能出现的合并冲突（如果有）

### 步骤6：推送目标分支到远程仓库
- 使用 `git push origin ${TARGET_BRANCH}` 命令将合并后的目标分支推送到远程仓库

### 步骤7：切换回源分支
- 使用 `git checkout ${SOURCE_BRANCH}` 命令切换回源分支

### 注意事项
- 确保在合并前没有未提交的修改
- 确保 ${SOURCE_BRANCH} 分支包含了所有需要合并的内容
- 处理可能出现的合并冲突
- 推送前检查合并结果

### 预期效果
- ${TARGET_BRANCH} 分支包含了 ${SOURCE_BRANCH} 分支的所有内容
- 成功推送到远程仓库
- 保持了良好的Git工作流

### 后续建议
- 考虑在合并前运行测试，确保所有测试通过
- 考虑在合并后创建标签，标记版本发布
- 确保团队成员知道这个合并操作
